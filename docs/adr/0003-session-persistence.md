# Session Persistence via Appended Session.vim Payload and Opt-in Autosave

Group state (`vim.w.group_bufs`) is persisted by appending one guarded `lua` line carrying a versioned JSON payload to the Session.vim file in a `SessionWritePost` autocmd, rather than writing a sidecar file or storing it in a `g:` variable. Neovim has no `SessionWritePre`, `:mksession` never writes `w:` variables, and the `globals` session option only saves strings and numbers (and would require users to change `sessionoptions`); appending keeps the state in the one file the user already manages, survives moving or renaming the session, and makes every `:mksession`-based workflow (manual, persistence.nvim, auto-session, mini.sessions) carry groups without depending on any of them. The appended line runs after `SessionLoadPost`/`unlet SessionLoad`, i.e. once the layout exists, and is wrapped in `pcall` so the session still loads without the plugin. Buffers are stored as absolute paths (bufnrs are not stable) and matched to restored windows primarily by the file each window displays — unique per tabpage thanks to single-membership — falling back to editor-window order; tabpages match by index. Group autocmds are suspended while `g:SessionLoad` is set so `find_owner` redirects cannot corrupt the layout mid-load.

On top of this, the plugin ships its own per-cwd session management (autosave on `VimLeavePre`, autoload on `VimEnter` for `nvim` or `nvim <dir>`, never with file arguments, stdin or headless) behind a single `session.autosave` switch, default `false`, plus `:WindowGroupsSession save|load|delete`. Save and load are one switch because neither is useful alone. It defaults off so upgrading never makes two session managers restore at once. Autosave only calls `:mksession`, so the same append path persists groups. `:WindowGroupsSession delete` pauses autosave for the rest of the Neovim instance (until a manual save), otherwise the next exit would silently recreate the session the user just deleted. The cost is that autoload depends on the plugin being loaded before `VimEnter`; lazy-loaded setups miss the event, which `setup()` mitigates via `vim.v.vim_did_enter` and the docs must call out prominently (`lazy = false`). No resession.nvim adapter is shipped: resession does not use `:mksession`, and maintaining an integration for one third-party manager is out of scope.
